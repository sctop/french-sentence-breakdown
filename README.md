# 法语逐词解析 · Mot à Mot

一个纯前端、简体中文界面的法语学习单页应用。输入法语句子或段落，应用会按标点切句，通过
OpenAI Chat Completions 兼容接口逐词标注**标准英文词性**、**词典原形**、**英文释义**、
**英语近似读音**和 **IPA 转写**，为每个句子附上自然英文翻译，并允许把词语收藏到浏览器本地生词本。
也可以输入英语，先翻译成自然法语，再对法语译文做同样的逐词解析。

## 功能

- **逐词解析**：固定 JSON Schema 约束 LLM 输出，逐词显示 `n.` / `v.` / `adj.` 等英文词性与英文释义。
- **英→法翻译模式**：输入英语，先单独请求一次自然、地道的法语翻译，再用法语译文走同一套切句与
  逐词解析；翻译和分析是两次独立请求。
- **自然英文翻译**：每个法语句子下方以小字显示自然、地道的整句英文翻译，分析历史也会连同翻译保存。
- **词形简注**：对 v./aux./pron./det./n. 标注极简中文变形信息，如「直现·一单」「不定·阴单」「阴复」；
  其余词性不显示，避免表格噪音。
- **双读音标注**：每个词同时给出英语读者友好的近似读音（如 `a·skee`、`bohn·zhoor`）和标准 IPA
  转写（如 `/a.ski/`、`/bɔ̃.ʒuʁ/`），收藏时两者一并缓存。
- **自动切句**：按 `.` `;` `?` `!` 以及全角 `。；？！` 切分，支持缩略词、小数、引号和连续标点。
- **本地生词本**：缓存词语、词性、释义、原形、近似读音、IPA、来源句和保存时间；支持词性多选、时间区间筛选、
  原词/英文释义搜索、排序、删除撤销、清空。
- **分析历史**：每次完整成功的分析自动保存在本机，普通历史最多保留 100 次；重要记录可加星标，
  星标会单独持久保存，不参与普通历史上限，也不会被普通历史清理删除。星标可单独导出，或与生词本一起导出。
- **导入导出**：版本化 JSON 格式，导入时按「原词 + 词性」合并去重。
- **浏览器直连 LLM**：API 地址、密钥、模型保存在 localStorage，请求直接从浏览器发往配置的接口。
- **主题**：跟随系统 / 浅色 / 深色，选择即生效并记住。
- **隐私优先**：无后端、无统计、无外部字体与 CDN；除配置的 LLM 接口外不发起第三方请求。

## 技术栈

Vue 3.5 + Vite 8 + TypeScript 6 + Pinia 4 + Vue Router 5。无额外运行时依赖。

## 快速开始

需要 Node.js `^22.18.0 || >=24.12.0`（与 `package.json` 的 `engines` 一致）。

```sh
pnpm install
pnpm dev
```

生产构建与预览：

```sh
pnpm build
pnpm preview
```

自动化测试与代码检查：

```sh
pnpm test
pnpm type-check
pnpm lint
```

如果本机没有安装 pnpm，可将上述命令换成对应的 `npm run <script>`。

## 配置 API

打开「设置」页填写：

- **API 地址**：Base URL（如 `https://api.openai.com/v1`）或完整
  `…/chat/completions` 地址均可。
- **API 密钥**：仅保存在当前浏览器；无鉴权的本地接口可以留空。
- **模型**：例如 `gpt-4o-mini`、`deepseek-chat` 等，需支持 Chat Completions。

几点说明：

- 请求由浏览器直接发出，**API 必须允许跨域访问（CORS）**；否则会提示网络或 CORS 错误。
- 逐词分析默认优先使用 `response_format: { type: "json_schema", strict: true }`。如果接口返回
  HTTP 400/422，会自动降级为 `json_object` 兼容模式，并用同一结构在客户端校验结果。
- 英→法模式会先发送一次独立的纯文本翻译请求，提示词强调自然、地道、非逐词直译；随后再发送逐词
  分析请求。翻译请求不附加 JSON Schema，避免格式约束影响译文自然度；两次请求使用同一 API 与模型。
- 请求不设置 `temperature`、不启用流式传输，以兼容更多模型。
- LLM 逐句返回 `translation`（自然英文翻译）；逐词返回 `inflection`（v./aux./pron./det./n. 的中文简写
  变形信息，其他词性为空）、`respelling`（英语读者友好的近似读音，使用 `·` 分音节）和 `ipa`
  （带斜杠的标准 IPA）。翻译、变形信息与读音会连同分析历史保存，读音在收藏时一并缓存。
- 「测试连接」会请求 `GET {base}/models`，不消耗补全额度；部分兼容接口不提供此端点。

当前真实接口需要你自己的密钥，应用不会附带任何预置服务。

## 切句与限制

- 句子边界为 `.`、`!`、`?`、`;`、`…` 及对应全角标点；紧跟其后的闭引号/闭括号会归入当前句。
- 小数点和常见称呼缩写（`M.`、`Mme.`、`Dr.` 等）不会被误切；冒号不切句。
- 单次输入上限 8000 字符、100 句；每 8 句或 1200 字符拆成一次分析请求，串行执行。
- 英→法模式下，翻译结果最长缓存 12000 字符；若翻译后超过 100 句，需缩短英文输入后重试。
- 某一批失败时会保留已完成结果，可只重试未完成的句子；已生成的法语译文不会重复翻译。

## 数据与隐私

所有数据都在当前浏览器：

| localStorage key    | 内容                                                                |
| ------------------- | ------------------------------------------------------------------- |
| `fsb:theme`         | `system` / `light` / `dark`                                         |
| `fsb:api:v1`        | `{ baseUrl, apiKey, model }`                                        |
| `fsb:vocabulary:v1` | `{ version: 1, entries: [...] }`                                    |
| `fsb:history:v1`    | `{ version: 1, records: [...], starred: [...] }`（普通最多 100 条） |

分析历史会在本机保存你提交的原文、英→法模式下的法语译文和完整解析结果，只有完整成功的分析才会写入；
失败或取消的分析不会记录。普通历史最多 100 条；星标记录独立于该上限，不会被普通历史淘汰或「清空普通历史」删除。如果 localStorage
空间不足，保存新历史时会自动清理较早的普通记录，星标记录不会被自动清理；仍然放不下时会在界面上提示。

API 密钥以**明文**保存在 localStorage。请使用权限受限的密钥，不要在公共电脑上保存，
并注意任何能在本站运行的脚本都可能读取它。配置的 LLM 服务会收到你提交的分析文本或待翻译英语；
除此之外应用不会把数据发送到其他地方。

## 分析历史与星标

- 每次分析的所有句子均成功完成后，自动写入一条普通历史；普通历史最多 `100` 条，超出后淘汰最早记录。
- 历史页可查看时间、句数、词数和原文预览，点击「载入解析页」会把对应输入、模式（含英→法译文）与
  完整解析结果恢复到解析页，然后可以继续收藏生词。
- 点击「星标」会把记录从普通历史移入「星标记录」：星标记录单独持久保存，不参与 100 条上限，
  不会被普通历史淘汰，也不会被「清空普通历史」删除。
- 取消星标后，记录会回到普通历史；此时若普通历史已满，会按上限淘汰最早的普通记录。星标记录没有
  直接的删除按钮，需先取消星标再处理。
- 普通历史可逐条删除或清空，清空需要二次确认；星标记录会保留。
- 历史仅保存在当前浏览器；清理浏览器存储会删除全部普通与星标记录。

### 星标导出与合并备份

- 历史页的「导出星标历史」导出版本化 JSON：
  `format` 为 `french-sentence-breakdown/starred-history`，包含 `records` 数组。
- 建议同时导出：历史页的「导出生词本 + 星标」或生词本页的同名按钮会生成合并备份，
  `format` 为 `french-sentence-breakdown/backup`，包含 `vocabulary` 与 `starredHistory` 两个数组。
- 备份文件仅用于导出；当前不提供星标历史/合并备份的导入。

## 生词本导入导出

导出的 JSON 结构如下：

```json
{
  "format": "french-sentence-breakdown/vocabulary",
  "version": 1,
  "exportedAt": "2026-06-09T12:00:00.000Z",
  "entries": [
    {
      "id": "b2f2…",
      "word": "pomme",
      "pos": "n.",
      "lemma": "pomme",
      "meaning": "apple",
      "respelling": "pom",
      "ipa": "/pɔm/",
      "context": "Je mange une pomme.",
      "addedAt": "2026-06-09T11:30:00.000Z"
    }
  ]
}
```

导入接受上述 envelope 或裸数组，单文件最大 5MB、最多 10000 条。按小写原词 + 词性去重，
已存在的词会跳过，缺失或无效的字段会被忽略并在结果中计数。

## 部署

`pnpm build` 输出纯静态文件到 `dist/`。应用使用 History 路由，静态托管时需要把未知路径
回退到 `index.html`（例如 Nginx 的 `try_files $uri $uri/ /index.html;`），否则直接刷新
`/history`、`/vocabulary` 或 `/settings` 会 404。

## 测试

`pnpm test` 使用 Node 内置测试运行器，不依赖额外测试框架，覆盖切句、批次划分、词性归一化、
搜索归一化、导入导出、自然英文翻译、英→法独立翻译请求、变形简注与近似读音/IPA 解析、普通历史保留上限与星标持久化、星标/合并备份、LLM 响应解析、JSON Schema 请求与 400 兼容降级等核心逻辑。

## 浏览器支持

面向现代 Chrome / Edge / Firefox / Safari。需要 Fetch、AbortController、CSS 变量和
`Intl.DateTimeFormat`；`crypto.randomUUID` 不可用时自动降级。
